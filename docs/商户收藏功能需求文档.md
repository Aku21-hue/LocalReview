## 1. 背景与目标

### 1.1 背景
当前项目已实现商铺查询、关注、点赞、Feed 流等功能，但用户无法对感兴趣商户做长期收藏标记。在「附近商户」「商铺详情」页浏览后，需要入口集中管理感兴趣的店铺。

### 1.2 目标
- 用户可对任一商户执行「收藏 / 取消收藏」操作。
- 在商铺详情页可直观看到当前用户是否已收藏该商铺。
- 用户可在「我的收藏」页查看收藏列表，支持分页。
- 提供「共同收藏」社交化入口，复用现有 Set 交集能力，与"共同关注"形成对称功能点。

### 1.3 非目标（不做范围）
- 不做收藏夹分组（如"想去的店""吃过的店"等分组）。
- 不做收藏导出 / 分享 / 推送。
- 不做收藏排序（按收藏时间倒序即可，不做按距离/评分排序）。
- 不做收藏离线缓存与同步。
- 不做商户维度的"被收藏数"实时统计（如需后续可单独实现）。

## 2. 名词与约定

| 名词 | 含义 |
|------|------|
| 收藏者 | 当前登录用户（来自 `UserHolder.getUser().getId()`） |
| 目标商户 | 被收藏的 `tb_shop` 记录 |
| isCollect | 接口路径参数，`true` 表示收藏，`false` 表示取消 |

**风格约定**：本模块在命名、API 风格、Redis Key 设计、表结构上与 [FollowServiceImpl.java](../src/main/java/com/hmdp/service/impl/FollowServiceImpl.java) 保持一致，方便后续维护。

## 4. 接口设计

> 路径前缀：`/collect`
> 全部接口走 [MvcConfig.java](../src/main/java/com/hmdp/config/MvcConfig.java) 中已配置的 `LoginInterceptor`，未登录返回 401。

### 4.1 收藏 / 取消收藏

```
PUT /collect/{id}/{isCollect}
```

| 参数 | 位置 | 类型 | 说明 |
|------|------|------|------|
| id | path | Long | 商户 id |
| isCollect | path | Boolean | true=收藏，false=取消 |

**响应**
```json
{ "success": true, "data": null }
```

**校验**
- 商铺 id 必须存在（`tb_shop` 中存在），不存在返回 `Result.fail("商铺不存在")`。
- 收藏幂等：重复收藏直接返回 ok，不报错。
- 取消幂等：未收藏时取消也返回 ok。

### 4.2 查询是否已收藏

```
GET /collect/or/not/{id}
```

**响应**
```json
{ "success": true, "data": true }
```

### 4.3 我的收藏列表（分页）

```
GET /collect/list?current=1
```

| 参数 | 位置 | 类型 | 默认 | 说明 |
|------|------|------|------|------|
| current | query | Integer | 1 | 页码 |

**响应**：返回 `Shop` 列表（与 [ShopController](../src/main/java/com/hmdp/controller/ShopController.java) 返回结构一致），按收藏时间倒序。

```json
{
  "success": true,
  "data": [
    { "id": 1, "name": "...", "typeId": 10, ... }
  ]
}
```

**实现要点**
- 由于收藏关系存放在 Redis Set 中（无序），需结合 MySQL `tb_collect` 的 `create_time` 排序。
- 单页大小复用 [SystemConstants.MAX_PAGE_SIZE](../src/main/java/com/hmdp/utils/SystemConstants.java)。

### 4.4 共同收藏

```
GET /collect/common/{id}
```

| 参数 | 位置 | 类型 | 说明 |
|------|------|------|------|
| id | path | Long | 另一用户 id |

**响应**：返回 `Shop` 列表（最多前 N 个，N 由 `SystemConstants` 常量控制，建议 20）。

```json
{
  "success": true,
  "data": [ { "id": 1, "name": "..." } ]
}
```

**实现要点**
- 使用 Redis `SINTER` 求两个用户收藏集合的交集。
- 与 [FollowServiceImpl#followCommons](../src/main/java/com/hmdp/service/impl/FollowServiceImpl.java#L78-L98) 同构。

## 5. 数据模型

### 5.1 新增表：`tb_collect`

参照 [tb_follow](../src/main/resources/db/hmdp.sql#L71-L78) 风格：

```sql
DROP TABLE IF EXISTS `tb_collect`;
CREATE TABLE `tb_collect` (
  `id` bigint(20) NOT NULL AUTO_INCREMENT COMMENT '主键',
  `user_id` bigint(20) UNSIGNED NOT NULL COMMENT '收藏者用户id',
  `shop_id` bigint(20) UNSIGNED NOT NULL COMMENT '被收藏的商户id',
  `create_time` timestamp NOT NULL DEFAULT CURRENT_TIMESTAMP COMMENT '收藏时间',
  PRIMARY KEY (`id`) USING BTREE,
  UNIQUE KEY `uk_user_shop` (`user_id`, `shop_id`) USING BTREE,
  KEY `idx_user_create` (`user_id`, `create_time`) USING BTREE
) ENGINE = InnoDB CHARACTER SET = utf8mb4 COLLATE = utf8mb4_general_ci COMMENT = '用户商户收藏关系表' ROW_FORMAT = Compact;
```

**说明**
- `uk_user_shop` 唯一索引：DB 层兜底防重，与"收藏幂等"配合。
- `idx_user_create`：覆盖"我的收藏列表"按时间倒序分页查询。

### 5.2 Redis Key 设计

在 [RedisConstants.java](../src/main/java/com/hmdp/utils/RedisConstants.java) 中新增常量：

```java
public static final String COLLECT_KEY = "collects:user:";   // 用户收藏集合
```

**Key 形态**：`collects:user:{userId}`
**数据结构**：Set，元素为 `shopId`（字符串）
**用途**：共同收藏的 `SINTER`、是否已收藏的 `SISMEMBER`

> 不为收藏列表分页单独维护 ZSet（按时间排序），分页查询直接读 MySQL，避免过度设计；共同收藏走 Redis 即可。

### 5.3 缓存策略

| 操作 | Redis 处理 |
|------|------------|
| 收藏成功 | `SADD collects:user:{uid} {shopId}` |
| 取消成功 | `SREM collects:user:{uid} {shopId}` |
| 是否已收藏 | 优先 `SISMEMBER`，未命中回 DB 查 `tb_collect` |
| 共同收藏 | `SINTER collects:user:{a} collects:user:{b}` |

**数据一致性**
- Redis 与 MySQL 双写：先写 MySQL（save/remove），成功后再写 Redis（与 [FollowServiceImpl.java:50-53](../src/main/java/com/hmdp/service/impl/FollowServiceImpl.java#L50-L53) 一致）。
- 不引入分布式事务；Redis 写失败仅记日志，下次"是否已收藏"会触发回 DB 校验并自愈。

```java
@Data
@Accessors(chain = true)
@TableName("tb_collect")
public class Collect implements Serializable {
    @TableId(value = "id", type = IdType.AUTO)
    private Long id;
    private Long userId;
    private Long shopId;
    private LocalDateTime createTime;
}
```

**Service Impl 核心方法骨架**
```java
@Override
public Result collect(Long shopId, Boolean isCollect) {
    Long userId = UserHolder.getUser().getId();
    String key = RedisConstants.COLLECT_KEY + userId;
    if (isCollect) {
        // 幂等：先查，已存在则直接返回 ok
        Collect c = new Collect().setUserId(userId).setShopId(shopId);
        boolean ok = saveOrUpdateIdempotent(c); // 内部用唯一索引兜底
        if (ok) stringRedisTemplate.opsForSet().add(key, shopId.toString());
    } else {
        boolean ok = remove(new QueryWrapper<Collect>()
                .eq("user_id", userId).eq("shop_id", shopId));
        if (ok) stringRedisTemplate.opsForSet().remove(key, shopId.toString());
    }
    return Result.ok();
}
```

> 详细 SQL/Mapper/Controller 全量代码在实现阶段补充，需求阶段仅约定骨架与签名。

## 7. 关键技术点

| 项 | 方案 |
|----|------|
| 数据结构 | Redis Set（成员=shopId） |
| 共同收藏 | `SINTER`（与 `followCommons` 同构） |
| 防重 | DB 唯一索引 `uk_user_shop` + 业务层幂等返回 |
| 一致性 | 先 DB 后 Redis；Redis 失败不回滚，自愈式校验 |
| 分页 | 复用 `SystemConstants.MAX_PAGE_SIZE` + MyBatis-Plus `Page` |
| 鉴权 | 复用现有 `LoginInterceptor`，无新增拦截器 |

## 8. 测试点

### 8.1 功能测试
- [ ] 未登录访问任意 `/collect/**` → 401
- [ ] 收藏不存在的 shopId → 提示商铺不存在
- [ ] 收藏 → DB 落库 + Redis SADD
- [ ] 重复收藏 → 幂等成功
- [ ] 取消收藏 → DB 删除 + Redis SREM
- [ ] 未收藏时取消 → 幂等成功
- [ ] 是否已收藏：已收藏返回 true，未收藏返回 false
- [ ] 我的收藏列表：分页正确、按时间倒序
- [ ] 共同收藏：返回两用户都收藏的商铺列表；无交集返回空数组

### 8.2 边界 / 一致性
- [ ] Redis 容器重建后：是否已收藏回 DB 校验自愈
- [ ] Redis 写成功但 DB 失败：抛异常，Redis 未写入（事务内）
- [ ] Redis 写失败但 DB 成功：日志告警，下次查询触发回填（高级项，可选）

### 8.3 压测（可选）
- [ ] QPS 1000 的收藏 / 取消切换，无重复行
- [ ] 共同收藏接口 P99 < 50ms（基于 Redis SINTER）

## 9. 验收标准

1. 4 个接口（4.1–4.4）全部按本文档响应结构返回，Postman/前端联调通过。
2. `tb_collect` 表存在唯一索引 `uk_user_shop`，并发收藏不产生重复行。
3. Redis Key 命名严格使用 `collects:user:{userId}`。
4. 代码风格与 `Follow` 模块对齐：包结构、命名、Redis Key 风格一致。
5. 不引入新中间件、新依赖；不修改鉴权拦截器逻辑（除非必要）。

## 10. 后续可选扩展（本期不做）

- 商户维度"被收藏总数"：使用 `Hash` 字段 `shop:collected:count` + 定时任务刷新。
